What it is

Onehostbox brings two things that normally live apart into one platform: AI-assisted code, and the hosting that runs it. Both work directly from a Git repository, so the repository is the single point of connection between changing an application and running it — there is no separate pipeline to assemble in between.

It is live, it launched in 2026, and it is a product in its own right rather than a tool we happened to write for one project. It lives at onehostbox.com.

Who it's for

Two kinds of people use it. Developers connect a GitHub repository and get builds, deploys and hosting without writing pipeline configuration. People who don't write code describe the site they want in plain English, watch the AI build it, refine it in conversation, and publish it — then hand it over to a developer later by ejecting it to GitHub.

What's in it

  • Deploys from Git. Connect a GitHub repository; every push to the production branch builds and ships automatically.
  • Zero configuration. Detects the framework and build command. No YAML, no Dockerfiles.
  • Preview URLs. Every pull request gets its own preview deploy.
  • Instant rollback. Every deploy is versioned and immutable; roll back to any previous build in one click.
  • Custom domains with HTTPS. Bring your own domain; certificates are issued and renewed automatically.
  • Global delivery. Sites are served from CloudFront edge locations worldwide.
  • AI builder. Generate a site from a description, refine it in plain English, and eject it to your own GitHub repository at any time.
  • Environment variables. Injected at build time and never shown in deploy logs.

Why we build our own product

Client work and product work teach different things. Shipping a feature is a deadline; operating a platform is a decade. Running Onehostbox means we carry the consequences of our own infrastructure decisions — the migrations, the incidents, the cost curve — rather than handing them to someone else at launch.

That experience goes directly into the cloud and DevOps work we do for clients. When we recommend a boring, well-understood architecture, it is because we are the ones who would be woken up by the interesting one.
